## Activity rules

| Surface or condition | Illustration |
| --- | --- |
| Home | New grounded student checking an upright phone on a campus bench, looking ahead with an open free hand. No money exchange or hoop. |
| Welcome / friend transfer / request | Original campus peers with phones and Ghanaian textile clothing. |
| Initial Chat | New student actively asking a question on the phone. Active conversation hides intro art. |
| General payment, bill, review or PIN | New student checking/tapping an upright phone. Recipient, fee, product and authorisation remain real interface text. |
| Selected Campus Pay food merchant | Original food counter. The merchant picker and non-food merchants do not inherit a food scene. |
| Pause / defer / cancel | New student considering the phone before acting. A supported laptop-only goal trade-off may use the original laptop scene. Essential shortfalls remain neutral decisions rather than an unrelated purchase. |
| Plan / allowance / generic or mixed goals | Original notebook. Expected allowance is never illustrated as received funds. |
| Selected existing laptop goal | Original laptop scene. New goals and the overall Plan do not assume a laptop. |
| Ghana-card/identity ownership checks | New student holding an upright phone and blank ID card. No fabricated official card text or crest. |
| Account details / records / receipts / support report | New student checking a notebook with a phone on the desk. Support art does not imply a connected human service. |
| Funding before a result | Payment-phone action or bank-details record review. No cash handover or success celebration. |
| Funding confirmed | Existing relaxed phone-checking scene, only when the active funding reference identifies an actual incoming success. |
| Payment confirmed | Existing phone-checking scene. Food handover additionally requires a Campus Pay Food category and explicit delivered status. Financial success alone is not proof of physical delivery. |
| Pending / failed / reversed / unknown result | Neutral phone consideration, explicit existing interface status and no completed-purchase scene. |
