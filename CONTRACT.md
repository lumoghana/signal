# Lumo new experience

Buildless ES modules. Root owns index.html, app.js, ui.js, style.css, registration and deployment. Each agent owns its named files only. Do not use Git or Sites tools.

All monetary values are integer pesewas. `cash(12500)` renders `GH₵125.00`.

## State
`{version:1,onboardingDone,profile:{name,phone,campus},wallet,buffer,income:{amount,nextDate},budget:{items:[{id,name,emoji,amount,spent,due}],created},boxes:[{id,name,emoji,target,balance,deadline,hack:{type,value},locked}],transactions:[{id,type,direction,amount,merchant,category,status,at,note,emoji}],ious:[{id,name,type:'owedToMe'|'owedByMe',amount,due,status:'open'|'settled',note}],groups:[{id,name,emoji,target,balance,members:[{id,name,amount,role}],mandate:{approvers,threshold},payouts:[]}],settings:{hideBalance:true,notifications:true,pin:'1234'},recovery:null}`.

`getSummary(s)` returns `{available,planned,spendable,savings,total,expected,daysLeft,dailyAllowance}`. Planned = remaining budget + due outgoing IOUs; incoming IOUs/expected allowance never count as available. Savings separate from wallet. Budget reservation is not a transfer.

## Model API (model.js)
`createDemoState()`, `createEmptyState(profile={})`, `loadState()`, `saveState(s)`, `getSummary(s)`, `evaluatePayment(s,{amount,category,recipient})`, `applyAction(s,type,payload)`. Apply mutates state and returns `{ok,message,...}`. Required actions: fund, payment, reversePayment, createBudget, updateBudget, deleteBudgetItem, createBox, updateBox, contributeBox, withdrawBox, deleteBox, createIOU, settleIOU, createGroup, contributeGroup, requestPayout, approvePayout, executePayout, recoveryPlan, updateProfile, settings. Payload amounts in pesewas. All actions validate and prevent duplicate execution using optional payload.idempotencyKey.

## View API
`renderPayments(ctx,route)` + `bindPayments(ctx,route)` from payments.js; routes `{section:'pay',page:'home'|'collect'|'recipient'|'amount'|'review'|'pause'|'status'|'transaction',...}`.
`renderPlanning(ctx,route)` + `bindPlanning(ctx,route)` + optional `afterPlanning(ctx,route)` from planning.js; routes `{section:'plan'|'boxes',page:'home'|'create'|'detail'|'edit'|'hack',id?}`.
`renderLife(ctx,route)` + `bindLife(ctx,route)` from life.js; routes `{section:'life',page:'overview'|'ious'|'iou-detail'|'recovery'|'groups'|'group-detail'|'story'|'settings'|'help',id?}`.
`renderChat(ctx,route)` + `bindChat(ctx,route)` from chat.js; route `{section:'chat',page:'home'}`.

Views return HTML strings. Bind adds event listeners after mount. `ctx.state` is current state, `ctx.route` current route, `ctx.go(route)` navigates (with history), `ctx.back()`, `ctx.refresh()` rerenders. `ctx.act(type,payload)` saves on success but DOES NOT rerender. `ctx.toast(text)`. `ctx.sheet(html,bindCallback)` opens an accessible modal bottom sheet and invokes callback with sheet element. `ctx.closeSheet()`. `ctx.auth({title,onSuccess})` opens demo PIN 1234 UI. `ctx.celebrate({title,body,button,onDone})` celebratory full-screen overlay. `ctx.draft` is an in-memory object for flows; `ctx.$(selector)` and `ctx.$$(selector)` query main view. Agents may use DOM directly scoped to #view or their sheet.

## Focused camera signup with demo verification
`onboarding-model.js` owns schema 6 and seven focused pages: name, phone, code, card-number, selfie, identity-review, pin. Name, phone and card number each have their own page. Camera consent and all three centre/turn/blink captures belong to the selfie page. After the automatic verification animation succeeds, selfie completion opens the dedicated returned-details review. Explicit confirmation there is required before PIN. PIN and its confirmation share one page. Completion creates both zero-funded simulated accounts, with no invented expected income or cushion. Money and campus preferences are optional after signup.

`renderOnboarding(ctx,route)` / `bindOnboarding(ctx,route)` use `ctx.draft.onboarding`; bind returns camera/timer cleanup. `camera.js` owns real getUserMedia with audio disabled, readiness, cropped JPEG capture and cancellation-safe cleanup. The selfie page opens a single front-camera stream for all three prompts and updates its DOM between captures. `recordSelfieCapture(draft,prompt)` is called only after a successful actual snapshot. The UI also checks its in-memory photos before advancing. After capture three, `beginIdentityVerification()` issues an attempt token; the animated simulation resolves only that current attempt using `resolveIdentityVerification()`. Success returns a transient sample record bound to the card number. `confirmIdentityDetails()` records explicit customer confirmation. Neither three captures alone nor a successful result without confirmation can open PIN. Retake, mismatch, number/consent/phone changes and media loss invalidate the record and confirmation. A cancelled attempt cannot later succeed.

Ghana Card numbers and photos must never enter persisted state or server requests. `persistableOnboardingDraft()` returns a sanitized saved clone, removing every raw number copy, returned record and verification attempt, and invalidating identity proof without modifying the live draft. Root uses it when saving sessionStorage. `clearOnboardingMedia(draft)` disposes streams and revokes all three selfie URLs. `resetCameraCaptures()` removes the raw number and proof on exit/reload/unload; `resetLiveness()` supports an in-page retake while retaining the number. Normal route cleanup stops the stream and keeps photos for Back/Forward within signup, especially selfie → identity-review → PIN. Retaking selfies preserves the completed card-number step; changing the card number invalidates the card-number step and everything after it. Exit/reload clears private details and returns to card-number while preserving accepted name, phone and OTP. Hidden pages stop streams and cancel pending verification. The animation helper uses a cancellable scheduler; successful confirmations remain valid during ordinary movement to PIN. BFCache restore re-clamps the route.

`ctx.completeOnboarding()` consumes all seven completed steps and assigns the new account only for first signup. It uses the confirmed sample record for `profile.legalName` and both accounts’ `holderName`, preserving the chosen display name. No raw card number or returned date of birth is persisted in account state. Preview completion discards the generated account and keeps existing financial state. `ctx.exitOnboarding()` retains earlier answers and returns to Welcome or Settings. Legacy draft/route migration must map older aggregated pages safely and never resurrect front/back card photos, money setup, recap or account-processing screens. Verification remains explicitly simulated; do not claim biometric detection, face matching or NIA verification. Demo OTP: 123456. Demo Ghana Card: GHA-000000000-0. Public demo PIN: 1234.
